# 豆包私有语音通道 · 可行性探针结论

探针日期：2026-09-13　目标版本：豆包输入法 Windows 0.9.0.0　预算：半天

---

## 1. 结论

**判定：通（Go）—— 豆包自己的语音识别通道可以在无管理员权限下被独立进程使用，但需要两处运行时内存补丁，不能纯命令行直接调用。**

| 验证项 | 结果 |
| --- | --- |
| 无管理员权限运行 | ✅ 通过（全程 Medium 完整性级别） |
| 不注册 TSF、不装系统输入法 | ✅ 通过（只用用户目录里的程序副本） |
| 不依赖 `C:\Windows\System32` 下的组件 | ✅ 通过（副本自定位） |
| 不依赖 HKLM 注册表 | ✅ 通过（712 次注册表访问中 0 次指向 Doubao/Obric 键） |
| 拿到语音识别结果 | ✅ 通过（会话 200 OK、增量结果、final `valid=1 full_vad=1 bytes=105`、退出码 0） |
| 直接看到"字面文本" | ⚠️ 未闭环（厂商日志对用户文本脱敏，见 §5） |
| 纯命令行直接可用 | ❌ 不成立（必须先绕过 2 个检查点，见 §3） |

启动时的硬门槛：`ImeService.exe` 清单为 `asInvoker + uiAccess="true"`，普通用户直接启动会报
"The requested operation requires elevation"。本次用**用户级** AppCompat shim（`RUNASINVOKER`，
写在 `HKCU\...\AppCompatFlags\Layers`）绕过，全程未提权。

## 2. 关键发现（架构与入口）

- **官方自测入口**：`ImeService.exe --test-sami --wav <16k 单声道 16bit PCM WAV>`，内部走
  `SamiAsrClientWin::RunFileTest` → `FeedPcm16kMono`，即"喂一段音频，返回识别结果"。
- **采集在服务端**：`ImeService.exe` 内含 `waveInOpen / 16000Hz / 1ch / 16bit` 与
  `AudioDeviceEnumeratorWin::ResolveWaveInIndex`，即麦克风采集与 ASR 都在服务端进程内完成；
  前台应用里的 `tsf-oime-core.dll` 只负责发指令、取文本。
- **客户端 API 已公开导出**：`rpc.dll` 有 32 个 C 风格导出，含
  `CreateRpcClient`、`RpcPipe_EnsureServerRunning`、`RpcPipe_KeyEvent`、
  `RpcPipe_PeekVoiceCommitUtf8`、`RpcPipe_AckVoiceCommit`；`tsf-oime-core.dll` 正是通过其中
  23 个入口与 `\\.\pipe\ObricIme\oime-server` 通信。
- **云端通道**：`wss://frontier-audio-ime-quic.doubao.com/api/v1/ws`
  （备用 `wss://frontier-audio-ime-ws.doubao.com/ocean/api/v1/ws`），
  `appKey=OrnqKvSSrs`、`aid=685343`，鉴权字段是 `device_id`（无需用户登录）。
- **device_id 来源**：本机缓存 `%APPDATA%\DoubaoIme\ttnet\tt_net_config.config`
  （本次实测值 2521637083956824）与 `%APPDATA%\DoubaoIme\applog`。
- **日志脱敏**：日志里用户文本被替换（中文→`X`、字母→`M`、数字→`A`，标点保留），
  这是厂商的隐私设计，不是识别失败。

## 3. 为跑通所做的两处补丁（均在内存中，不改磁盘文件）

`--test-sami` 路径在 AppLog 运行时就绪**之前**就启动识别，导致：

| # | 位置（RVA） | 原始行为 | 补丁 |
| --- | --- | --- | --- |
| 1 | `0x717762` | `cmp qword [rdi+0x290], 0` → 为 0 时打印 "sami start skipped because AppLog did is not ready" 并放弃 | 命中时把该字段写成非空指针，放行 |
| 2 | `0x714893` | 令牌按 `{"device_id":"<did>","aid":"685343"}` 拼接时 did 为空 → `token ... is invalid`、`ret 100008` | 把 15 字符 DID 写入该 `std::string` 的 SSO 内联缓冲（不涉及堆分配） |

补丁 2 生效后日志出现 `Frontier config url: ..., did: 252163708395682, aid: 685343`，
会话随即建立。**注意：服务端接受的是"非空 device_id"，并未要求与本地 device 一致。**

## 5. 未闭环与局限

1. **没看到字面文本**。日志被强制脱敏，应用侧接收结果的函数参数不是明文 `char*`，
   探针预算内未能取出原文；间接证据是结构化结果（`result_len=296/750`、
   `words num=31`、`bytes=105`、VAD/stream 标志齐全）与静音反例为 0。
2. **必须打运行时补丁**，因此"纯 CLI 调用"不成立；产品化需要自带一个注入器/加载器。
3. **随版本失效**：两个补丁点都是硬编码 RVA，换版本需重新定位；`rpc.dll` 的 32 个导出
   相对稳定，但不保证。
4. **依赖用户级数据与联网**：需要 `%APPDATA%\DoubaoIme`（applog/TTNet 缓存）与到
   `*.doubao.com` 的网络。全新机器首次运行可能需要补齐这些缓存。
5. **单实例**：本机已装豆包在运行时，副本按"服务端模式"启动会打印
   `Server Already Exists.` 并退出；`--test-sami` 路径不受影响（本次全程未停过已装服务）。
6. **合规**：这是厂商私有接口与私有鉴权，未公开、很可能违反其用户协议；结论仅供本机自用，
   不发布、不外传、不用于商业分发。公司电脑上把语音送云端还可能触碰公司数据合规。

## 6. 若要做成产品（第二期）的边界

**可做**：便携目录（87MB 精简版即可）+ 启动器（注入上述补丁）+ 录音（16k 单声道 PCM）+
调用 `--test-sami` 或直接读回调 → 端到端"按住说话 → 文字落到光标"，
延迟 ≈ 说话时长 + 2~3 秒；无需管理员、无需 TSF、不改系统。

**不可做 / 不建议**：无补丁的纯命令行方案；把 `rpc.dll` 管道协议当作稳定接口；
把这套东西分发或商用。

**更优路线（未验证）**：直接用 `rpc.dll` 的
`CreateRpcClient → RpcPipe_EnsureServerRunning → RpcPipe_KeyEvent → RpcPipe_PeekVoiceCommitUtf8`
驱动服务端自己录音，可拿到流式、低延迟体验；签名需从 `tsf-oime-core.dll` 调用点还原。
